# 09 多轮会话管理

## 9.1 核心机制：thread_id

LangChain v1 通过 LangGraph 的 `thread_id` 实现多轮会话：

```python
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver
from langchain_core.messages import HumanMessage

agent = create_agent(
    model=model,
    tools=tools,
    checkpointer=InMemorySaver(),
)

# 同一 thread_id = 同一对话
config = {"configurable": {"thread_id": "session-user-123"}}

# 第 1 轮
await agent.ainvoke(
    {"messages": [HumanMessage("My name is Bob")]},
    config=config
)

# 第 2 轮（自动携带历史）
result = await agent.ainvoke(
    {"messages": [HumanMessage("What did I just tell you?")]},
    config=config
)
# → "You told me your name is Bob."
```

## 9.2 会话状态保存与恢复

每次 LangGraph 超步执行后，Checkpointer 自动保存：

```python
# 查看当前会话状态
state = await agent.aget_state(config)
print(state.values["messages"])       # 完整消息历史
print(state.next)                     # 下一个节点（如果中断）
print(state.config["configurable"])   # thread_id, checkpoint_id

# 查看历史检查点
async for checkpoint in agent.aget_state_history(config):
    print(checkpoint.config)          # 每个检查点的配置
    print(checkpoint.metadata)        # step, source, writes

# 恢复到特定检查点（时间旅行）
old_config = {
    "configurable": {
        "thread_id": "session-user-123",
        "checkpoint_id": "1e8f7c9a-..."  # 特定检查点
    }
}
result = await agent.ainvoke(
    {"messages": [HumanMessage("Try again from here")]},
    config=old_config
)
```

## 9.3 会话中断与恢复（Human-in-the-Loop）

```python
from langchain.agents.middleware import human_in_the_loop

agent = create_agent(
    model=model,
    tools=tools,
    checkpointer=InMemorySaver(),
    middleware=[human_in_the_loop(tools=["delete_file"])],
)

# 执行中遇到 "delete_file" 工具 → 中断
result = await agent.ainvoke({"messages": [HumanMessage("Delete old logs")]}, config)
# result.interrupted == True

# 人类确认后恢复
await agent.aupdate_state(
    config,
    {"human_approval": True}
)
# 继续执行
result = await agent.ainvoke(None, config)
```

## 9.4 流式多轮会话

```python
# 流式接收每个 token
async for event in agent.astream_events(
    {"messages": [HumanMessage("Tell me a story")]},
    config=config,
    version="v2"
):
    if event["event"] == "on_chat_model_stream":
        chunk = event["data"]["chunk"]
        print(chunk.content, end="", flush=True)

# 流式接收消息（结构化）
async for chunk in agent.astream(
    {"messages": [HumanMessage("Hello")]},
    config=config,
    stream_mode="messages"
):
    message, metadata = chunk
    if hasattr(message, "content"):
        print(message.content, end="", flush=True)
```

## 9.5 多用户隔离

```python
# 不同用户用不同 thread_id
async def handle_user_request(user_id: str, message: str):
    config = {"configurable": {"thread_id": f"user-{user_id}"}}
    return await agent.ainvoke(
        {"messages": [HumanMessage(message)]},
        config=config
    )

# Alice 和 Bob 的对话完全隔离
await handle_user_request("alice", "My name is Alice")
await handle_user_request("bob", "My name is Bob")
await handle_user_request("alice", "What is my name?")  # → "Alice"（不会混淆）
```

## 9.6 旧版 ConversationBufferMemory 对比

```python
# ❌ 旧版（已废弃）- 有状态竞争风险
from langchain.memory import ConversationBufferMemory
memory = ConversationBufferMemory()
chain = LLMChain(llm=llm, prompt=prompt, memory=memory)
# 所有用户共享同一个 memory 对象 → 并发时会混淆历史

# ✅ 新版 - 通过 thread_id 隔离
agent = create_agent(model=llm, tools=[], checkpointer=InMemorySaver())
# 每个 thread_id 完全隔离，天然线程安全
```

## 9.7 与其他项目多轮会话对比

| 特性 | LangChain (新版) | LangGraph | deer-flow | hermes-agent | nanobot | gstack |
|------|----------------|-----------|-----------|-------------|---------|--------|
| **会话隔离** | thread_id | thread_id | thread_id | 无 | 进程隔离 | claude 进程 |
| **历史存储** | Checkpointer | Checkpointer | Checkpointer | 无 | memdir/ | 无 |
| **持久化** | PostgreSQL | PostgreSQL | PostgreSQL | ❌ | 文件 | git commit |
| **中断恢复** | HITL 中间件 | interrupt API | 无 | 无 | 无 | 无 |
| **时间旅行** | ✅ (checkpoint_id) | ✅ | ✅ | ❌ | ❌ | ❌ |
| **流式** | astream_events | astream | astream | ❌ | ❌ | ✅ (PTY) |
| **并发安全** | ✅ | ✅ | ✅ | N/A | ✅ (进程隔离) | ✅ (进程隔离) |

**关键洞察：**
- LangChain v1 的多轮会话能力完全来自 LangGraph（它是 LangGraph 的封装层）
- 旧版 Classic Memory 的并发安全问题是废弃的主要原因之一
- `thread_id` 是现代 LangChain/LangGraph 应用的核心会话标识符
